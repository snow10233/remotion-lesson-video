# 2. 腳本：旁白、畫面、動作點

旁白就是整支影片的時間軸：每句（beat）有固定的 id（`場景.key`），音檔用這個 id 命名；字幕直接顯示旁白，配音也直接念旁白。每一句同時寫出「這句畫面要做什麼」，因為一句旁白配一段畫面動作，先寫完旁白再想畫面，容易寫出畫面接不上的句子。

## 寫在哪裡

直接寫進場景程式的 `beats`（格式見專案 `src/videos/_example/index.tsx`）：

```ts
{ key: "l3", text: "第 3 行先假設 P，｜註解寫 A。", after: 1.2 },  // 畫面：第 3 行出現；念到「註解」時框住註解欄
```

- `text` 裡的「｜」是動作點：畫面在念到「｜」後面那個字時動作。用 `cue("l3", 1)` 取得第 1 個「｜」的格數。
- 「｜」放在要講到的東西**前面**，例如「｜註解寫 A」，框就會在開口念「註解」時出現。對時用逐字對齊，放在句子任何地方都對得準，不必放在標點後面。
- `after`：最後一個動作點之後至少留幾秒給動畫；`min`：這句最少幾秒。動畫比話長時以動畫為準。
- 畫面要做什麼寫成註解，給 3B 做畫面時照著做。

## 旁白

- 語氣和語言照開工時選的旁白風格。英文專有名詞保留原文，術語第一次出現要解釋。
- 一句大約 20 到 70 字：一句就是一個音檔，太長模型會自己切段、中間出現怪停頓，太短畫面來不及做動作。
- 數學和程式符號寫成念出來的樣子：「小於等於」「n 平方」「O n」「log 以二為底」。數學式放在畫面上，旁白用念的。
- 數字序列用頓號隔開，例如「40、60、55」。
- 一句話裡依序講到好幾個東西時，每個東西前面放一個「｜」，畫面跟著依序變化，不要在句子一開始就全部跑完。

## 練習題

使用者要練習題時：題目出現 → 旁白念完題目 → 倒數 3、2、1 讓觀眾暫停作答 → 揭曉答案。揭曉時一定要說明理由，不能只給結論，因為答錯的觀眾需要知道錯在哪裡。

## 定稿

所有場景寫完，跑 `node scripts/export_tts.mjs <composition>` 匯出 `tts/<影片>/`，旁白就定稿了。之後：

- **可以**：新增、刪除、移動「｜」，改 `after`、`min`，改畫面。這些不影響念法，不用重配。
- **改字**：要重配那幾句，照 [`merge.md`](merge.md) 的「補做」處理。改標點也算改字（會改變停頓）。
